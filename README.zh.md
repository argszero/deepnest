# deepnest（深巢）

**本地优先的单文件应用生成器。**

一个可执行文件，双击运行，打开浏览器里的一个页面。你说出想要的应用，agent 就在你自己的机器上把它写出来 —— React 前端、Rust 后端、SQLite 存储 —— 边写边刷新。

> **状态：早期，但已经能跑。** 尚未发布任何版本。设计、沙箱、工具集、agent 循环、应用生成、控制面板与 skill 加载器都已进仓库：`cargo run -p deepnest` 会在 `http://127.0.0.1:4270/` 上起服务，在桌面浏览器里打开这张页面，并把控制令牌写到 `~/.deepnest/deepnest.token`。`https` 的模型端点已经能用，证书按本机自己的证书库校验。打包也在仓库里：二进制里嵌着一份工具链载荷，第一次用到时解包；`crates/bundle` 铺出 macOS 的 `.app` 并逐个签里面每个 Mach-O，CI 再把它做成经 `hdiutil verify` 校验的 `.dmg`。**还差的是一个发布，而它等的是两份输入，不是代码。** 载荷归档是构建输入 —— `payload/toolchain.zst`，或 `DEEPNEST_PAYLOAD` 指名的那个文件 —— 所以它不在仓库里；从源码跑出来的二进制不带载荷，用的是你机器上已有的工具链。签名要一张 Developer ID 证书和一个专用密码，而还没有任何 runner 拿着它们：今天的构建是 ad-hoc 签名，没有可信时间戳，也没有公证。

## 理念

**每个应用就是一个目录。** 源码、配置、SQLite 数据库和编译产物都放在 `~/.deepnest/` 下。没有远程编译服务器，也不需要云端账号：编译和运行都在你自己的机器上。

有一件事确实会离开本机，说明白比含糊好：agent 需要一个模型，而这个模型由你自己提供。你输入的需求和 agent 写出的代码，会发到**你自己配置的那个端点**，除此以外不外发。

**每个应用有自己的 agent。** 页面里有一个悬浮的对话框。你告诉它应用该做什么，它生成并修改代码，浏览器视图实时刷新。一个应用，一个目录，一个 agent。

**deepnest 本身是一个文件。** 约 140 MB，自包含。它带着生成应用所需要的东西 —— Rust 工具链和 JavaScript 运行时 —— 所以第一台机器上除了操作系统什么都不用装，就能编译出第一个应用。

## 「单文件」指的是 deepnest，不是你的应用

这个区分很重要，也容易弄反：

| | 是什么 |
|---|---|
| **deepnest** | 一个可执行文件，约 140 MB，双击即用 |
| **你生成的每个应用** | 一个目录：源码、配置、SQLite 数据库、编译产物 |

单文件是那个「生成器」。应用是普通的工程目录，可以打开、阅读、做版本管理、备份。

## 实测数字

以下是在一台 Apple 芯片的 Mac 上做打包设计时实测得到，不是估算：

| 测量项 | 结果 |
|---|---|
| 载荷体积（zstd -19，单线程） | 约 140 MB |
| 首次启动：解压自带工具链 | 937 ms |
| 生成第二个应用，复用共享编译缓存 | 4.25 s |
| 生成第二个应用，冷缓存 | 13.2 s |
| 小改动后重新编译 | 0.5 s |
| 空闲时常驻内存 | 5 MB |

载荷构成：最小的 Rust 工具链从 486 MB 压缩到 112 MB，JavaScript 运行时从 60 MB 压缩到 16 MB。

用 `xz` 能压到 59 MB，但压缩要 55 秒、解压要 2.9 秒 —— 已否决，首次启动必须保持在一秒左右。

## 系统要求

deepnest 不自带 C 工具链，也不打算自带：它体积大、与平台绑定，由操作系统自己的工具安装更合适。而 Rust/SQLite 这套技术栈需要编译 C。

- **macOS** —— Xcode Command Line Tools（`xcode-select --install`）
- **Windows** —— Visual Studio C++ Build Tools

deepnest 会在第一次编译前检查，缺什么就引导你装什么，而不是编译到一半才失败。

## 打开 macOS 上的构建

从这里下载到的构建，在没有 Developer ID 的情况下是 **ad-hoc 签名**，而不是由 Apple 身份签名。所以 macOS 第一次双击会拒绝它，提示无法验证开发者。

这是预期中的，也不是一句可以随手忽略的警告 —— 那正是签名能买到、而这个项目还没有的东西。要打开它：

1. 右键点击 `Deepnest.app`（或 `.dmg`），选 **打开**。
2. 在弹出的对话框里再点一次 **打开**。

macOS 会记住这一份副本的这个决定。已经用 Developer ID 签名并公证过的构建不需要这些步骤，双击即可；发行说明会写明某次下载属于哪一种。

## 关于这个名字

这里的 `deepnest` 与开源排样（nesting）工具 [Deepnest](https://deepnest.io) 及其移植版本无关。那是给激光、等离子、CNC 切割做排版优化的项目；这个项目生成应用。
